# 클러스터링 평가 셋 2026-11 — 판정 기준과 구성

> ⚠️ **2026-11-09 — 새 301쌍은 다시 뽑는다.** 아래 "새 301쌍"을 뽑은 사본 `disaster_alert_eval_kind` 는 라벨 쌍 주변 약 1.4만 건만 분류하고 나머지를 INCIDENT 로 채운 사본이라, "둘 다 사건" 조건이 제 역할을 못 해 퀴즈 307문항 중 약 78쌍에 비사건(호우 주의·산불 예방 안내 등)이 섞였다. 운영 DB 의 과거 알림을 분류 백필한 뒤 그 값을 새 사본(`disaster_alert_eval_v5`)에 옮겨 재클러스터링하고, 진짜 사건 쌍만 다시 뽑는다. 기존 96쌍의 기준 정정(7쌍)은 그대로 유효하다.

두 재난문자가 **같은 사건**인가? 이 셋은 **둘 다 "사건"(INCIDENT)으로 분류된 알림만** 쌍으로 뽑았다.
기준의 원본은 `docs/event-clustering/CLUSTERING_CRITERIA.md` 1절이다. 이 파일은 그 기준을 셋에 어떻게 적용했는지만 적는다.

## 판정 기준

1. 같은 지역에서 **하나의 사고·사건**이 이어지는 경우(발생 → 통제·대피 → 복구·해제 등 후속 문자) → **같은 사건**
2. 인접 지역이고 **같은 개체·현상이 이어진 경우**(사고 확산, 동물 이동 등, 문자에 연속성 단서가 있어야 함) → **같은 사건**
3. **별개의 사고·사건**(각각 다른 장소·번지의 화재, 서로 다른 지점의 시설 파손, 같은 날 따로 발생한 사고 등) → **다른 사건**

**경계 사례 (2026-11-09 사용자 확정 — 위보다 우선)**
- **A. 호우**: 같은 호우 동안 같은·이웃 시군구에서 서로 다른 곳에 난 침수·범람·도로 통제·해제·대피 → 같은 사건. 유형이 교통통제여도 원인이 같은 호우면 같다.
- **B. 산불 확산**: 큰 산불이 번지며 차례로 나온 대피명령·통제 → 문자에 이어짐 표시가 없어도 같은 사건.
- **C. 산불 별개 발화**: 같은 군·같은 날이어도 서로 다른 곳에서 각각 "발생"을 알리면 → 다른 사건.

판단이 안 서면 "모르겠음"(점수 계산에서 제외).

### 새 301쌍 — 기존 셋과 같은 틀로 뽑음
- **사본**: `disaster_alert_eval_kind`(분류 완비 — INCIDENT 50,714 / ADVISORY 11,840).
- **후보 알림**: `alert_kind = INCIDENT`, 임베딩 있음, 아래 유형. 시도 전체 코드(시군구 자리 `000`)는 시군구 매칭에서 뺐다.
