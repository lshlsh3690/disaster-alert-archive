# 연구 기록: 클러스터링 평가의 대표 지표를 균형 정확도로

명세: [spec.md](spec.md). 기술 컨텍스트에 남은 미정 사항은 없다. 아래는 설계에서 고른 것과 이유다.

## R1. "맞게 나눈 쌍"은 기존 계산기에서 함께 센다

- **결정**: `PairCounter` 가 지금 버리는 "사람은 다른 사건, 시스템도 다른 이벤트" 관측을 `correctlySeparated` 로 세고, `PairCountResult` 에 개수와 `separation()`(섞지 않은 비율)·`balancedAccuracy()` 를 더한다.
- **이유**: 오프라인 평가와 운영 일일 채점이 이미 같은 `PairCounter` 를 쓰므로(006 R5), 한 곳만 고치면 두 경로가 같은 정의를 쓴다. 모르겠음·미배정 제외 규칙도 그대로 따른다.
- **대안**: 균형 정확도 전용 계산기를 따로 둔다 — 같은 관측을 두 번 세고 제외 규칙이 갈라질 수 있어 기각.

## R2. 균형 정확도는 개수에서 바로 계산하고, 분모가 0 이면 비운다

- **결정**: 균형 정확도 = (맞게 묶음 ÷ 같은 사건 쌍 + 맞게 나눔 ÷ 다른 사건 쌍) ÷ 2 × 100. 같은 사건 쌍이나 다른 사건 쌍 중 하나라도 0 이면 `OptionalDouble.empty()`.
- **이유**: 기존 `score()`·`purity()` 와 같은 규칙(반올림한 비율을 다시 조합하지 않음, 분모 0 은 지어내지 않음)을 따른다. 한쪽만 있는 날에 50% 나 0% 를 내면 "찍은 것과 같음" 이나 "전부 틀림" 으로 잘못 읽힌다.
- **대안**: 한쪽 분모가 0 이면 다른 쪽 비율만 대표로 쓴다 — 날마다 대표 지표의 뜻이 바뀌어 기각.

## R3. 판단 없는 기준선은 결과 개수에서 계산한다

- **결정**: 같은 사건 쌍 수(맞게 묶음 + 과소병합)와 다른 사건 쌍 수(과병합 + 맞게 나눔)만으로 두 기준선의 개수를 만든다. 전부 묶음 = (맞게 묶음 = 같은 사건 쌍, 과병합 = 다른 사건 쌍), 전부 따로 = (과소병합 = 같은 사건 쌍, 맞게 나눔 = 다른 사건 쌍). JPA·Spring 을 쓰지 않는 순수 클래스(`TrivialBaselines`)에 둔다.
- **이유**: 시스템을 잰 것과 **같은 쌍 집합**(모르겠음·미배정을 뺀 쌍)에서 계산해야 분모가 맞는다. 결과 개수만으로 충분해 관측 목록이나 재클러스터링이 필요 없다. 헌법 VI(판정·계산 규칙은 순수 클래스).
- **대안**: 라벨 파일 전체(미배정 포함)로 계산 — 시스템 점수와 분모가 달라 비교가 어긋나 기각.

## R4. 리포트는 요약만 바꾸고 틀린 쌍 표는 그대로 둔다

- **결정**: `ReportFormatter` 요약의 첫 줄을 균형 정확도로 바꾸고, 그 아래에 빠짐없이 묶은 비율·섞지 않은 비율(분자/분모), 보조 지표(맞게 묶은 비율, F1), 판단 없는 기준선 두 항목을 둔다. 틀린 쌍 표의 형식·순서는 손대지 않는다.
- **이유**: 튜닝 판단의 1차 근거가 두 리포트의 diff(006 FR-013)다. 표가 바뀌면 이 변경 전후 리포트 비교가 노이즈로 가득 찬다(명세 FR-005, SC-002).
- **대안**: 요약을 표로 바꾼다 — 기존 리포트와의 diff 가 크게 늘어 기각.

## R5. 일일 기록은 기존 집계에서 복원하고 저장 형식을 유지한다

- **결정**: 맞게 나눈 쌍 수 = `pairCount - correctlyMerged - missed - overMerged - unsureCount - formatFailureCount`. 이 복원을 JPA·Spring 없는 `PairCountResult.fromDailyCounts(...)` 한 곳에 두고, 대시보드는 기존 여섯 집계값을 넘긴다. 일일 채점 로그는 같은 정의의 균형 정확도를 대표로 보인다. 저장 열·마이그레이션·백필은 추가하지 않는다.
- **근거 코드**: `ClusteringDailyScoreService.count`는 배정된 쌍의 SAME/DIFF만 `PairCounter`에 넣고, `toDayRow`는 전체 `judged.size()`와 UNSURE·형식 실패를 각각 저장한다. 따라서 여섯 범주가 전체 판정 수를 구성하고, 기존 집계만으로 빠진 한 범주를 복원할 수 있다.
- **예시**: 전체 100, 맞게 묶음 30, 과소병합 10, 과병합 5, 모르겠음 4, 형식 실패 1이면 맞게 나눔은 50이다. 쌍별 기록이 없어도 이 계산은 가능하다.
- **검증 전제**: 기존 여섯 집계값과 복원한 값은 모두 음수가 아니어야 한다. 로컬 운영 사본에서 확인하고, 쌍별 기록 수가 전체 판정 수와 같은 날에만 다시 센 값과 대조한다. 전제가 깨진 행은 0으로 보정하거나 쌍 기록 부재와 혼동하지 말고 데이터 오류로 보고해 적용 전에 원인을 확인한다.
- **대안**: 별도 열을 저장하고 쌍별 기록으로 백필 — 이미 복원 가능한 값을 중복 저장하고 쌍별 기록이 없는 날을 불필요하게 계산 불가로 만들므로 기각.

## R6. 대시보드 API 는 필드를 더하고 기존 필드는 그대로 둔다

- **결정**: 날짜 항목에 `correctlySeparated`·`separation`·`balancedAccuracy`를 더하되 기존 `Day`의 `NON_NULL` 직렬화를 유지한다. 따라서 프론트 타입은 `correctlySeparated?: number`, `separation?: Ratio`, `balancedAccuracy?: number`다. 날짜별 기록이 없으면 새 필드도 모두 생략한다. 기록은 있으나 한쪽 분모가 0이면 `balancedAccuracy`만 생략하고, 해당 Ratio는 분자·분모를 유지한 채 `percent: null`을 보낸다. 기존 `score`(F1)·`purity`·`completeness`의 이름·뜻은 그대로다. 화면은 균형 정확도를 대표로, F1을 보조로 보인다.
- **이유**: 기존 필드의 뜻을 바꾸면 이미 배포된 화면·테스트가 조용히 틀린 값을 보인다. 더하는 쪽이 안전하다.
- **대안**: `score` 를 균형 정확도로 바꾼다 — 필드 이름은 같고 뜻이 달라져 기각.

## R7. TDD 범위

- **결정**: 신규 핵심 테스트는 4개다: 맞게 나눈 쌍 세기 1개, 구성비 불변성 1개, 기존 일일 집계 복원 1개, 두 기준선 50% 1개. 리포트는 새 테스트를 추가하는 대신 기존 요약 기대값을 RED에서 새 계약에 맞게 바꾸고 균형 정확도 첫 줄·기준선·보조 F1을 확인한다. 기존 세 개수와 F1 수치, 틀린 쌍 표 회귀 단정은 보존한다. GREEN에서는 테스트를 수정하지 않는다. 분모 0은 R2의 계약이며 기존 리포트 표시 검사와 quickstart의 응답 확인으로 검증한다. 표시 반올림은 기존 `ClusteringDashboardMetrics.roundPercent`를 재사용한다.
- **이유**: CLAUDE.md 의 Red-Green 규칙과 "Red 는 핵심 로직만"(2026-10-27) 규칙.

## R8. 문서 갱신 범위

- **결정**: 006 명세 FR-011·FR-016, 006 quickstart 의 "점수 하나와 그 재료 둘" 절과 "지표를 늘리지 않는다" 문장, `backend/evaluation/README.md` 의 리포트 읽는 법, 008 명세·quickstart의 일일 점수 표시 서술과 `contracts/admin-clustering-api.md`의 새 필드·키 생략 규칙을 고친다. 평가 README의 리포트 비교에는 실행 시각 한 줄 정규화를 명시한다. 지난 리포트(`backend/evaluation/reports/`)와 006 research 의 과거 수치는 기록으로 둔다.
- **이유**: 명세 FR-011·SC-005. 006 은 지표 정의의 원래 출처라 거기를 고쳐야 문서가 하나로 모인다.

## R9. 구성비 불변성 입력은 클래스별 배수를 다르게 한다

- **결정**: (맞게 묶음, 과소병합, 과병합, 맞게 나눔) = (8, 2, 1, 9)와 (16, 4, 1, 9)를 비교한다. 같은 사건 쌍만 2배라 구성비는 1:1에서 2:1로 변하고, 두 클래스 정답률은 80%·90%로 같아 균형 정확도는 둘 다 85.0%다.
- **이유**: 양쪽에 같은 배수를 곱하면 구성비가 변하지 않아 F1도 불변이다. 위 두 입력에서는 F1이 약 84.2에서 86.5로 변하므로 SC-003이 요구하는 상황을 실제로 만든다.

## R10. 리포트 회귀에서는 실행 시각만 제외한다

- **결정**: `EvaluationRunTool`이 `LocalDateTime.now()`를 기록하므로 두 리포트에서 `- 실행 시각: `로 시작하는 한 줄만 제거한 복사본을 비교한다. 원본 리포트는 그대로 두고 데이터셋 머리글·틀린 쌍 표·추가 절은 비교에서 제외하지 않는다. 기존 세 개수와 F1은 새 요약의 보조 항목과 값으로 대조한다.
- **이유**: 요약 표현은 의도적으로 바뀌지만 실행 시각은 기능 차이가 아니다. 정규화 뒤에는 요약 절 밖에 차이가 없어야 하며, 원본의 고정 시각 지원 같은 제품 기능은 추가하지 않는다.
