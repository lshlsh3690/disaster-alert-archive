# 결정 기록: 클러스터링 관리자 대시보드

기술 컨텍스트에 남은 미정 사항은 없다. 아래는 계획 단계에서 정한 것과 그 이유다.

## R1. 데이터는 지금 쌓이는 두 검증 기록만 쓴다

- **결정**: `clustering_daily_score`·`clustering_daily_score_pair`(01:00 일일 채점), `clustering_daily_check`(00:30 구조 검사)와 알림 원문만 읽는다. 새 테이블·마이그레이션 없음.
- **이유**: spec 의 네 영역이 모두 이 기록으로 채워진다. 2026-10-25 설계의 재료였던 판정 기록(`clustering_trace`)은 2026-11-08 삭제됐고 되살리지 않는다.
- **대안**: 대시보드용 요약 테이블을 따로 만들기 — 하루 1행이라 조회가 가벼워 필요 없다.

## R2. 판사 버전별 모델·일치율·단가를 한 곳(`JudgeVersionCatalog`)으로 모은다

- **결정**: 버전 → (모델, 같은 사건·다른 사건 일치율, 입력·출력 단가, 측정일)을 순수 클래스 하나에 두고, `ClusteringJudge.agreementOf`·`MODEL` 과 `JudgeAgreementReport` 단가가 그것을 읽게 한다.
- **이유**: 지금 세 곳에 흩어져 있어, 2026-11-18 모델을 바꿀 때 리포트 단가를 놓쳐 비용이 16배로 찍혔다. 대시보드까지 네 번째 사본을 만들면 같은 실수가 반복된다.
- **대안**: 대시보드에 버전 표를 따로 하드코딩 — 사본이 늘어 거부. DB 에 버전 표 저장 — 버전은 코드(프롬프트)와 함께 바뀌므로 코드에 두는 편이 맞다.

## R3. 날짜별 줄의 일치율은 그날 기록의 당시 값을 보여 준다

- **결정**: 일일 채점 표의 일치율은 `clustering_daily_score` 행에 복사된 값. 버전 이력 표의 일치율은 `JudgeVersionCatalog` 의 현재 값.
- **이유**: 006 R6 대로 날짜별 기록에 당시 일치율을 복사해 두었다. 상수를 나중에 고쳐도 과거 점수의 신뢰도 표시가 바뀌면 안 된다.

## R4. 점수 정의는 `PairCountResult` 를 그대로 쓴다

- **결정**: 맞게 묶은 비율·빠짐없이 묶은 비율·점수는 저장된 개수로 `PairCountResult` 를 만들어 그 메서드로 계산한다.
- **이유**: 튜닝 평가·일일 채점·대시보드가 같은 지표 정의를 쓴다(006 FR-011). 대시보드에서 다시 구현하면 정의가 갈릴 수 있다.

## R5. 알림 원문은 `disasteralert` 맥락의 service 를 거친다

- **결정**: `DisasterAlertService` 에 "id 목록 → (id, 원문, 발송 시각, 유형)" 조회를 추가해 쓴다.
- **이유**: 헌법 VII(개정 중) 취지 — 다른 맥락의 저장소를 직접 주입하지 않는다. 불일치 쌍 한 페이지(20쌍, 알림 최대 40건)를 한 번에 읽어 N+1 을 피한다.
- **대안**: `AssignmentReader`(평가 패키지, JdbcTemplate)를 재사용 — 평가 도구용이고 알림당 쿼리 2번이라 화면용으로 맞지 않음.

## R6. 조회 범위는 최대 366일, 기본 최근 30일

- **결정**: 시작 ≤ 끝, 길이 366일 이하가 아니면 `ErrorCode` 로 거부. 화면 기본은 오늘 제외 최근 30일.
- **이유**: 하루 1행이라 1년도 가볍지만, 상한이 없으면 실수로 아주 넓은 범위를 요청할 수 있다(spec 예외 상황).

## R7. 불일치 쌍은 페이지당 20쌍, 종류 필터

- **결정**: `page`·`size`(기본 20, 최대 100), `kind`(OVER_MERGED·MISSED·전체). 정렬은 날짜 내림차순 → 쌍 id 오름차순.
- **이유**: 큰 재난 날은 불일치 쌍이 수백~수천일 수 있다(2025-03-25 산불 날 판정 대상 1.2만 쌍). 한 번에 다 내려보내지 않는다.

## R8. 숫자 표만, 차트는 쓰지 않는다

- **결정**: 네 영역 모두 표. 추세 그래프는 이번 범위 밖.
- **이유**: 사용자는 "N개 중 M개" 같은 단순한 숫자를 원한다(평가 지표 기록). 그래프 라이브러리를 새로 들이지 않는다.

## R9. 관리자 판별은 백엔드가 최종, 프론트는 안내만

- **결정**: 백엔드는 `@PreAuthorize("hasRole('ADMIN')")`(기존 관리자 컨트롤러와 같음). 프론트는 `authStore.role` 로 비관리자에게 안내만 보이고 API 를 부르지 않는다.
- **이유**: 프론트 판별은 우회될 수 있어 보안 경계가 아니다. 백엔드 거부가 최종이다.
