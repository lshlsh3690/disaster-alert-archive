# 이벤트 클러스터링 유형별 기준

새 재난문자를 **어느 이벤트에 넣을지, 새 이벤트로 만들지**를 정하는 기준만 적은 문서다. 이 문서가 기준의 기준 문서이고, 다른 문서(`CLAUDE.md`, `specs/001-event-clustering-pipeline`)는 기준을 다시 쓰지 않고 이 문서를 참고한다. 기준을 바꾸면 이 문서를 먼저 고친다.

- 값의 원본은 `backend/src/main/resources/application.yml`의 `clustering.*`이다. 아래에는 현재 값과 설정 키를 같이 적는다.
- 구현 절차는 `specs/001-event-clustering-pipeline/`, 평가 방법과 측정 결과는 `docs/CLUSTERING_EVALUATION.md`를 본다. 이 문서에는 절차·성능 수치·이력을 적지 않는다.

---

## 1. 같은 사건의 정의

두 재난문자가 같은 사건인지는 다음 세 가지로 판정한다(사건 알림끼리의 판정).

1. 같은 지역에서 **하나의 사고·사건**이 이어지는 경우(발생 → 통제·대피 → 복구·해제 등 후속 문자) → **같은 사건**
2. 인접 지역이고 **같은 개체·현상이 이어진 경우**(산불·사고 확산, 동물 이동 등, 문자에 연속성 단서가 있어야 함) → **같은 사건**
3. **별개의 사고·사건**(각각 다른 장소·번지의 화재, 서로 다른 지점의 시설 파손, 같은 날 따로 발생한 사고 등) → **다른 사건**

---

## 2. 어떤 알림을 클러스터링하는가

알림은 수집 직후 LLM으로 **사건(INCIDENT) / 비사건(ADVISORY)** 으로 분류해 `disaster_alert.alert_kind`에 저장한다.

| `alert_kind` | 클러스터링 |
|---|---|
| `ADVISORY` (비사건: 특보·예방 안내 등) | **하지 않는다.** 이벤트를 만들지도 기존 이벤트에 넣지도 않는다 |
| `INCIDENT` (사건) | 한다 |
| `null` (분류 실패, 분류 도입 전의 알림) | 한다. 분류 실패가 사건을 이벤트에서 빼면 안 되기 때문이다 |

- 실종 수배("OOO씨를 찾습니다")는 `INCIDENT`로 저장한다.
- 분류 응답은 `INCIDENT` / `ADVISORY` / `MISSING_PERSON` 한 단어와 정확히 일치할 때만 받아들인다(앞뒤 공백·대소문자 무시). 부정문·혼합 답은 `null`이다.

---

## 3. 처리 순서

위에서부터 판단하고, 먼저 걸린 경로가 처리하면 아래 단계는 건너뛴다.

| 순서 | 경로 | 대상 |
|---|---|---|
| 0 | 비사건 제외 | `alert_kind == ADVISORY` |
| 1 | 신원 키 | 실종 인물 |
| 2 | 유형만 키 | 태풍(`clustering.global-types`) |
| 3 | 유형+시군구 키 (지역 한정) | 산불·산사태·홍수(`clustering.regional-types`) |
| 4 | 유형+시군구 키 (에피소드형) | 폭염·한파·대설·강풍·가축질병(`clustering.episodic-types`) |
| 5 | 안내 이벤트 | 산불의 안내, `기타`의 물놀이·수상안전 안내(`clustering.advisory-split-types`). `alert_kind`가 `null`인 알림에만 해당 |
| 6 | 임베딩 경로 | 위에 걸리지 않은 모든 유형 |
| (별도 패스) | cross-region | 지역을 넘나드는 `기타`(동물 탈출·출몰, 실종 이동) |

지역 코드가 없는 알림은 후보를 검색할 수 없으므로 항상 새 이벤트를 만든다.

---

## 4. 유형별 기준

### 실종자 (`기타` + 이름·나이가 있는 수배 문자)
- **키**: 신원(이름 + 나이 + 키). 지역·본문 유사도는 보지 않는다.
- **같은 사건**: 같은 신원의 재신고. 윈도우 14일(`person-window-hours` 336h).
- **다른 사건**: 이름·나이·키 중 하나라도 다른 사람(같은 시군구여도 다름).

### 태풍
- **키**: 재난유형만. 지역과 무관하게 전국 단일 이벤트로 묶는다.
- **같은 사건**: 마지막 알림 후 168시간 이내의 태풍 알림 전부(`global-window-hours`).

### 산불
- **키**: 유형 + 시군구. 같은 시군구의 마지막 알림이 168시간 이내인 이벤트에 병합한다(`regional-types` 산불:168). 본문은 보지 않는다.
- **인접 병합**: 같은 시군구에 병합할 이벤트가 없으면, 인접 시군구(`region_adjacency`)에서 **마지막 알림이 24시간 이내**인 산불 이벤트에 병합한다(`regional-adjacent-types`, `regional-adjacent-window-hours`). 시군구 개수 상한은 없다.
- **다른 사건**: 168시간을 넘겨 비었다가 다시 난 산불, 24시간을 넘겨 시간이 안 겹치는 인접 시군구의 산불.
- 지역 한정 경로에서 처리가 끝나므로 임베딩·LLM 폴백을 거치지 않는다. 시군구가 10개를 넘는 알림은 광역 경로로 간다.

### 산사태·홍수
- **키**: 유형 + 시군구, 마지막 알림 후 168시간 이내(`regional-types`). 인접 병합은 없다.
- **다른 사건**: 168시간을 넘긴 재발, 시군구가 다른 알림(병렬로 안내되는 같은 비도 시군구별로 따로 본다).

### 폭염·한파·대설·강풍·가축질병 (에피소드형)
- **키**: 유형 + 시군구. 같은 시군구에서 발령이 끊기지 않고 이어지는 동안 하나의 이벤트로 이어 붙인다. 끊김 기준은 **마지막 알림 후 168시간**(`episodic-window-hours`).
- 시군구가 정확히 **1개**인 알림만 이 키를 쓴다. **2개 이상**이면 지역 이벤트와 섞이지 않게 광역 경로로 보낸다.
- 임베딩 경로에서의 병합 유사도 하한 완화(`relaxed-threshold-types`, 유사도 0.65 = 거리 0.35)는 이 유형군에만 적용된다.
- 이 유형은 안내와 특보를 분리하지 않고 한 이벤트로 합친다(비사건으로 분류된 알림은 2절에 따라 클러스터링되지 않는다).

### 사고성 (화재·교통사고·교통통제·교통·붕괴·환경오염사고·정전·통신·테러·지진·지진해일·수도)
- **임베딩 경로**:
  1. 같은 시군구(시군구 코드 앞 5자리 교집합) 후보 중 마지막 알림이 168시간 이내인 이벤트를 코사인 거리 오름차순 상위 3개로 뽑는다.
  2. 거리 **0.15 이하**(유사도 0.85 이상, `similarity-threshold`)인 후보에 병합한다.
  3. 병합에 실패하면 인접 시군구 후보를 임계값만으로 검사한다(`adjacent-window-hours` 48h, 후보 이벤트 첫 알림이 72시간 이내여야 함, `adjacent-max-event-age-hours`). LLM은 쓰지 않는다.
  4. 그래도 실패하면 LLM 폴백: 같은 시군구 후보 중 거리가 **0.15 초과 0.40 이하**인 후보를 "같은 원인의 사건인가"로 판정한다(`llm-fallback.distance-ceil`). 실패·모호하면 병합하지 않는다.
  5. 모두 실패하면 새 이벤트를 만든다.
- **화재 가드**: 이벤트의 마지막 알림이 72시간을 넘었으면 LLM 폴백·인접 병합 후보에서 제외한다(별개 화재 오병합 방지).
- **LLM 폴백 대상 유형**: `llm-fallback.accident-types`. 후보 이벤트도 사고성 유형이어야 한다. 동물·비정형 알림(`animal-keywords`)은 제외한다.
- **다른 사건**: 같은 시군구여도 번지·시설·장소가 다른 사고.

### 호우
- 에피소드형도 사고성도 아니므로 **임베딩 경로**만 탄다(키 병합 없음). 같은 시군구 후보에 거리 0.15 이하일 때 병합한다.
- LLM 폴백 대상이 아니다.

### `기타`
- **물놀이·수상안전 예방 안내**: 시군구별 안내 이벤트(윈도우 `advisory-window-hours` 168h)에 모으고 이웃 시군구와는 병합하지 않는다. 사건 신호(익수·실종 등)가 있으면 안내가 아니다. `alert_kind`가 `null`인 알림에만 해당한다.
- **동물 탈출·출몰·실종 이동**: `mover-keywords`로 걸러 같은 지역이 아니어도 후보 상위 5개(유사도 0.6 이상, 14일 윈도우)를 뽑아 LLM이 같은 개체인지 판정한다(`cross-region.*`). 이벤트가 30건 또는 10개 시도를 넘으면 더 묶지 않는다.
- 그 밖의 `기타`: 임베딩 경로 + LLM 폴백(사고성 유형으로 등록됨).

### 그 외 유형 (풍랑·건조·미세먼지·황사 등)
- 별도 규칙이 없고 **임베딩 경로**를 탄다.

### 광역 (한 알림이 여러 시군구에 발송된 경우)
- 시군구가 **10개를 초과**하면(`max-region-span`) 광역 경로로 보낸다. 에피소드형은 시군구 2개 이상이면 광역 경로다.
- **키**: 시도 + 유형(알림에서 시군구가 가장 많은 시도). 걸친 시도가 **8개 이상**이면 전국 + 유형(`nationwide-sido-span`)이다.
- 광역 이벤트는 지역 이벤트와 섞지 않는다.
- 유형이 `기타`이거나 비어 있으면 본문이 제각각이라 병합하지 않고 알림마다 새 이벤트를 만든다.

## 5. 공통 기준

- **지역 일치**: 시군구는 법정동 코드 앞 5자리로 비교하고, 이벤트가 걸친 모든 알림의 지역(footprint)과 새 알림 지역의 교집합으로 판단한다.
- **윈도우**: 이벤트의 **마지막 알림** 이후 경과 시간이 기준이다. 예외로 인접 병합의 이벤트 나이 상한(72시간)만 첫 알림 기준이다.
- **쿨다운**(이벤트가 진행 중인지)은 병합 기준이 아니라 별개 개념이며 유형별로 `DisasterCooldown`이 정한다.
