# 법정동코드 재발급(인천 구 재편·화성 구 신설·읍 승격) 반영 런북

> 작성: 2026-10-07. 브랜치 `feat/legal-district-reissue-incheon-hwaseong` 의 마이그레이션 V123 · V125 · V126 에 대한 기록이다.
> 이 문서는 **무엇을 했는지**, **배포하면 무엇이 일어나는지**, **일부러 보류한 것**을 남긴다.

## 1. 배경

공식 법정동코드 전체자료(행정표준코드관리시스템, 53,403행)와 우리 `legal_district`(53,063행)를 비교했더니 차이가 있었다.

- 공식에만 있는 340행(활성 338행), 공식은 폐지인데 우리는 활성인 332행. 우리에만 있는 코드는 0건.
- 원인: 인천 중·동·서구가 제물포·영종·서해·검단구로 재편, 화성시에 만세·효행·병점·동탄구 신설, 달성군 구지면·용인 처인구 양지면·음성군 대소면의 읍 승격, 리·동 개명 4쌍.

## 3. 배포하면 일어나는 일

**운영 DB에서 되돌릴 수 없는 변경이 있다.** 배포 시 Flyway가 자동으로 실행한다.

1. **관심지역 구독 삭제.** `member_favorite_region`, `guest_fcm_region` 에서 폐지된 옛 코드(332개)와 화성시(`4159000000`) 구독이 삭제된다. 새 코드로 옮기지 않는다 — 사용자가 새 지역명으로 다시 구독해야 한다.
2. **알림 이력 복제.** 옛 인천 중·서구 구 단위 알림은 새 구 두 곳에 모두 걸리고(복제), 옛 행은 삭제된다. 지역별 알림 집계가 그만큼 늘어난다.
3. **이벤트 주 지역 캐시.** `disaster_events.primary_region_code` 는 새 코드가 하나로 정해지는 경우만 갱신하고, 후보가 둘 이상이면(중구·서구 구 단위, 화성 능동) 옛 코드를 유지한다.

### 배포 후 사용자에게 보이는 현상

- 옛 인천·화성 등을 관심지역으로 두었던 사용자는 **알림이 오지 않게 된다.** 앱은 이를 알리지 않는다(아래 4번 보류 항목).
- 화성 새 구 4개와 그 하위 행, 개명 4쌍의 새 코드는 번역 행이 없어 **EN·JA·ZH 화면에서도 한국어로 표시된다.** `LegalDistrictTranslationService` 는 요청 언어 → 영어 → 한국어 순으로 대체한다.

### 배포 전 권장 (선택, 직접 실행)

구독 삭제는 되돌릴 수 없으므로 DB 백업을 권장한다. 영향 규모는 아래 근사 쿼리로 볼 수 있다(이미 폐지된 코드의 구독이 섞일 수 있어 근사치).

```sql
-- 삭제될 구독 수 (근사)
SELECT 'member_favorite_region' AS t, count(*) FROM member_favorite_region
WHERE legal_district_code ~ '^(2811|2814|2826|4159|2771038|4146136|4377034)' OR legal_district_code IN ('4777036038','4822025025')
UNION ALL
SELECT 'guest_fcm_region', count(*) FROM guest_fcm_region
WHERE legal_district_code ~ '^(2811|2814|2826|4159|2771038|4146136|4377034)' OR legal_district_code IN ('4777036038','4822025025');
```

```bash
# 영향받는 두 테이블 백업 예시 (컨테이너/DB 이름은 환경에 맞게)
pg_dump -U postgres -d disaster_alert -t member_favorite_region -t guest_fcm_region > legal_district_reissue_backup.sql
```

## 5. 보류 항목 상세: 옛 구에 남은 위험도 진원

`region_risk_index / history / daily` 는 5자리 시군구 코드 기반이다. 인천 옛 구는 새 구로 갈라져 **어느 새 구로 옮길지 정할 근거가 없어** V123 은 이 테이블들을 이관하지 않고, V126 은 옛 코드(28110·28140·28260)의 인접 간선만 제거한다.

- 운영 DB에 옛 코드의 **양수 `source_score`** 가 있으면, 간선을 제거해도 그 코드 자체의 위험도(홉 0)는 남을 수 있다.
- 로컬 DB에는 해당 행이 0건이다. **운영은 확인하지 않았다.**

운영에서 확인하는 쿼리(읽기 전용):

```sql
SELECT region_code, source_score, risk_score, updated_at
FROM region_risk_index
WHERE region_code IN ('28110','28140','28260') AND source_score > 0;
```

양수 행이 있으면 정리 방법(삭제 / 새 구로 복제 / 방치 후 감쇠)을 별도로 정해야 한다. `RiskDecayScheduler` 가 시간에 따라 점수를 감쇠시키므로 방치해도 시간이 지나면 줄어든다(이 동작은 문서·코드로 확인한 서술이며 실제 감쇠 속도는 확인하지 않았다).
