# 결정: PostGIS 를 앱 런타임에 도입하지 않는다

결정일: 2026-10-09. 상태: 확정(아래 "다시 검토할 신호"가 생기면 재검토).

## 결정

- 앱(운영·개발·테스트 DB)에는 PostGIS 를 도입하지 않는다.
- PostGIS 는 **오프라인 도구**로만 쓴다. 지도 경계 데이터와 인접 그래프를 만들 때 임시 컨테이너에서 돌리고,
  앱은 그 결과물(정적 JSON, `region_adjacency` 행)만 사용한다.

## 현재 사용 현황

| 용도 | 방식 | 위치 |
|---|---|---|
| 지도 경계(시군구 256개, 읍면동 약 5,000개) 생성 | 임시 PostGIS 컨테이너에서 투영·단순화·병합 후 정적 JSON 으로 출력 | `frontend/scripts/map-regions/`, 결과는 `frontend/public/map/**` (합계 3.6MB) |
| 시군구 인접 그래프 계산 | 경계 교차 길이로 이웃 판정 후 `region_adjacency` 행 생성 | V126 주석의 재현 절차, V122 |

앱 DB 의 확장은 `plpgsql`, `vector`(pgvector)뿐이고, geometry 컬럼이나 `ST_` 함수를 쓰는 앱 코드는 없다.
개발은 `pgvector/pgvector:pg15`, 운영은 `pgvector/pgvector:pg16` 이미지를 쓴다.

## 근거

1. **공간 연산 수요가 없다.**
   - 좌표 컬럼이 어느 테이블에도 없다. 알림은 지역명·법정동 코드로 들어오고 좌표는 오지 않는다.
   - 반경 검색, 점-폴리곤 판정, 경계 겹침 계산 같은 질의가 없다.
   - 날씨는 법정동 코드별 기상청 격자(`nx`, `ny`) 정적 매핑(`weather_station_mapping`)이다.
   - 위험도 확산은 좌표가 아니라 `region_adjacency` 위의 다중소스 BFS 다.
   - 사용자 제보 지역은 법정동 코드를 선택하는 방식이다.
2. **지도는 정적 산출물로 충분하다.** 읍면동 약 5,000개 폴리곤은 PostGIS 가 필요한 규모가 아니다.
   시도 단위 파일로 나눠 필요한 만큼만 받는다.
3. **병목이 있다면 관계형 문제다.** 법정동 데이터 증가로 생길 수 있는 비용은 `legal_district` 전체 조회, `left(code, N)` 그룹핑,
   인덱스 부재 같은 쿼리·인덱스 문제이고, PostGIS 로 풀리지 않는다.

## 도입 비용 (검토했지만 하지 않은 이유)

- 운영 이미지가 pgvector 이미지라 PostGIS 와 pgvector 를 함께 쓰려면 커스텀 이미지가 필요하다.
- 개발·테스트·운영(맥북 셀프호스팅) 이미지를 모두 맞춰야 하고, `CREATE EXTENSION` 권한·백업/복원·버전 업그레이드가
  확장에 묶인다.
- 맥북(arm64)에서 PostGIS 이미지가 호환되는지는 **확인하지 못했다.** 도입을 검토한다면 가장 먼저 확인할 위험이다.

## 다시 검토할 신호

아래 요구가 실제로 생기면 이 결정을 다시 본다.

- 좌표로 법정동을 찾아야 할 때 (예: "내 위치로 관심지역 설정", 좌표 기반 제보)
- 반경 알림·검색 (예: "주변 N km")
- 정적 JSON 대신 지도 타일·GeoJSON 을 API 로 동적으로 내려줘야 할 때
- 행정구역 개편마다 인접 그래프를 수작업으로 갱신하는 부담이 커질 때

## 개편 때 갱신하는 방법

행정구역이 바뀌면 오프라인 도구를 다시 돌린다.

- 경계 데이터: `frontend/scripts/map-regions/README.md` 의 `generate.sh` 절차로 재생성하고
  `frontend/src/lib/queries/useMapRegions.ts` 의 `MAP_DATA_VERSION` 을 올린다.
- 인접 그래프: V126 주석의 재현 절차를 따라 새 마이그레이션(`V{n}`)으로 `region_adjacency` 를 교체한다.
  이미 적용된 마이그레이션은 수정하지 않는다.
